Что медленно, и где уходит время

Вы назвали три медленных места. Для каждого есть замер. Зелёная метка «measured» — число измерено на настоящем файле. Синяя «tiled copy» — тот же файл, продолженный до длины 10 и 60 минут (экстраполяция по числу кадров). Жёлтая «expected» — выигрыш ожидаем, пока не сделан.

Код Python почти не тратит времени. Задержка, скорее всего, в браузере: он перерисовывает все трейсы. Это не измерено.

Почему щелчок дорогой. Один Delete делает 8 полных копий всех оценок (copy.deepcopy, 19 мс каждая на 2 000 кадров, 58 мс на 107 107) и 2 копии данных графика. Потом отправляет в браузер весь набор данных заново. Две трети набора — ось времени, продублированная для каждого нейрона.

Как измеряли

  • Файл: H:\Projects\_bearmind_test\series_short\5_Inspection\NOF_H01_1D\NOF_H01_1D_processed.pickle, 2 000 кадров, 194 нейрона, изображение 608×608, 82 МБ. Файл читали только на чтение.
  • Сервер Bokeh и браузер не запускали. Вызывали настоящие функции bm_examinator и настоящие обработчики кнопок на объекте-документе в памяти.
  • «Tiled copy» — тот же файл, продолженный по времени до 18 000 и 107 107 кадров (10 и 60 минут). Это экстраполяция по числу кадров, а не настоящая запись. В настоящей сессии нейронов может быть больше, тогда всё станет медленнее.
  • Не измерено: перерисовка в браузере, пересылка по сети, чтение с холодного диска.
  • Merge мерили на 4_Estimates (224 нейрона): в файле из 5_Inspection разреженная матрица S не подходит для CaImAn manual_merge.

Путь сессии через инспекцию

CNMF-E готов→waits ручной инспекции→вы: Manual inspection, чистите, Save results→решение cleaned записано само→батч берёт автоинспекцию

Ждёт только эта сессия. Остальные идут дальше. Отдельной кнопки «cleaned» нет: решение пишет само сохранение. Если чистить нечего, нажмите Not needed (фаза 2).

Если что-то пошло не так

закрыли браузер без сохранения→решения нет, сессия ждёт→сервер сам завершается
нажали Save results дважды→файл один, последний; решение «cleaned»
CNMF-E пересчитали, пока окно открыто→окно пишет «result is outdated»; решение не записывается
вторая инспекция той же сессии→второй сервер не стартует, сообщение называет адрес первого

Результат инспекции сохраняется без сжатия. Сжатие перепутало бы признаки для ML-фильтра автоинспекции.

Ошибка «не тот нейрон после удаления»

Эту ошибку чинит отдельная задача, прямо сейчас. Она не входит в фазу 5. Ускорение ниже не зависит от неё.

Где план расходится с вашими решениями

  • Скорость. План: «логику окна инспекции не менять», правки только в обвязке. Вы просите существенно ускорить удаление, склейку, переход и сохранение. Это требует менять внутренности обработчиков del / merge / show / revert и сохранения. Нужен ваш ответ: разрешаете ли менять эти обработчики (поведение для вас прежнее, внутри другое).
  • Процесс на сессию. План запускает отдельный процесс python -m bearmind inspect SERIES SID на каждую сессию. Быстрый переход к следующей требует одного долгоживущего сервера на серию. План придётся поправить.
  • Язык. План пишет кнопку «Ручная инспекция», статус «Инспекция … открывается в браузере…», «Результат устарел: CNMF-E пересчитан…» по-русски. На макете всё по-английски.
  • Новые пакеты. План: «новых пакетов нет». Теперь можно ставить пакеты в окружение bearmind, если они не конфликтуют с CaImAn. Для ускорения это может понадобиться (например, быстрая запись CSV); пока не требуется.
  • Мало главных предупреждений. План (задача 4) добавляет новое предупреждение «похоже на кальциевую волну». Фаза 2 зафиксировала шесть видов. Решите: добавить седьмой вид или показывать волну только в списке ждущих инспекции.

Что вы одобряете

  • Инспекция открывается из сводки кнопкой Manual inspection, в браузере; окно BEARMiND свободно.
  • Результат лежит в 5_Inspection и сохраняется без сжатия; «cleaned» пишется само при Save results.
  • Разрешение менять внутренности обработчиков, чтобы действия стали быстрыми (первая строка таблицы изменений).
  • Один сервер инспекции на серию и фоновая подготовка следующей сессии вместо процесса на каждую.
  • Сохранение в фоне: «cleaned» сразу после записи главного файла.
  • После фазы замеряем те же числа и показываем вам рядом с прежними.

Если что-то не так, назовите номер части. Например: «5 — не трогать Merge», «6 — оставить CSV синхронно».
