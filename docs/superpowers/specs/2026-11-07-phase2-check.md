## Находки (код не менялся)

1. Заголовки «Warnings — …» и «Log — …» не в верхнем регистре. `_section_label` делает `.upper()` только при создании, а последующий `setText` (`monitor_tab.py`, строки 258 и 501, заголовок лога) его обходит. Косметика.
2. Текст предупреждения повторяет название этапа («CNMF-E: …» после «· CNMF-E»). Видно на `lt1-running.png`.
3. Размер окна по умолчанию 1100x700: таблица и предупреждения сжаты до 2-3 строк, лог занимает столько же места (`lt1-running-1100x700.png`).
4. Данные LT1: скан нашёл 24 сессии (мыши J03, J05, J14, J27, J55, J61) с частотой 19,76 кадр/с при медиане серии 30,59, а также 7 `frames_ts_mismatch` и 55 `dropped_frames`. Окно показывает 24 предупреждения «fps … differs from series median», они отодвигают в списке предупреждения этапов (MC 18 px — восьмое из 27, см. часть 5). Это данные, не дефект окна, но порядок списка стоит обдумать.
5. Время обновления почти целиком определяет `psutil.Process(pid).create_time()` в `monitor._holds_lock`, когда есть `run.lock`: 65-130 мс на обновление (см. шаг 5).

### Почему оценка времени такая большая

Синтетические этапы DONE длятся ровно 3600 с. Когда у этапа два и больше завершённых записей, медиана истории заменяет число из `defaults.yaml`. Отсюда секунд на кадр: crop 0,139 (по умолчанию 0,0001), MC, пороги, CNMF-E, autoinspect и export около 0,2016 (по умолчанию 0,046 / 0,071 / 0,14 / 0,017 / 0,0005). При медиане 17 862 кадра это около часа на каждый оставшийся этап. Большая часть из 84 сессий почти не начата, отсюда ~35 дней. Это следствие синтетики, не ошибка окна. На реальных длительностях оценка станет реальной.

Причина прежней задержки на этой машине: `psutil.Process.status()` (около 280 мс, опрос всей системы; на Windows он не нужен, зомби бывают только в POSIX) и проверка мёртвого PID (около 60 мс). Теперь процесс владельца замка запоминается по PID, а «процесс замка завершился» — по содержимому замка. Без замка обновление стало на 3-4 мс дольше. Вероятная причина — новые проверки на каждом обновлении: окно само определяет сессии, которые батч не может поставить в расписание, и ожидание ручной инспекции (обе с кэшем, но с чтением дат изменения конфигов). Профиль не снимался. До порога 200 мс далеко.
