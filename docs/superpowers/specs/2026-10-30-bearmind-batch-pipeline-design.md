# BEARMiND: пакетная обработка серий с минимальным участием человека

Дизайн, 2026-10-30. Ветка `bearmind-batch`. Автор требований — В. Плюснин; формулировки «моё решение» — решения Claude, которые автор может отменить.

## 1. Зачем

Лаборатория снимает серии по десятки–сотни сессий минископа. Сейчас серия проходит BEARMiND через ноутбук `BEARMiND_full_pipeline.ipynb`: окна выбора файлов в 14 ячейках, ползунки кропа, массивы порогов CNMF-E, набранные руками, подгонка имён файлов срезами строк. Больше всего мешает именно ручной ввод порогов и подгонка имён. Без человека сейчас работают только автоинспекция и экспорт.

Цель: человек выбирает папку серии, разбирает аномалии, один раз подбирает пороги CNMF-E, запускает батч и дальше только изредка смотрит на мониторинг. В конце он получает экспорт проинспектированных компонент и сводку метаданных, по которой решает, какие сессии исключить или переанализировать.

Пользователи: автор и студенты, которых он обучит. Они не правят код и ячейки ноутбука.

## 2. Цели, не-цели, анти-цели

**Цели**
- Весь путь от папки сырых видео до экспорта (`npz`, `json`, `mat`) управляется конфигами и окнами. Ни путей, ни имён файлов, ни порогов руками в код не вносят.
- Пайплайн сам находит сессии, раскладывает их по мышам и сам находит выходы предыдущего этапа.
- После каждого этапа идут автоматические проверки; всё найденное пишется в метаданные.
- Батч переживает падения и перезагрузки: повторный запуск продолжает с места остановки.
- Убраны хардкоды, костыли, копии кода и найденные баги (приложение А).
- Уже обработанные серии подхватываются без прогона от сырых видео: можно открыть ручную инспекцию, переэкспортировать или продолжить с готового этапа (5.16). Прогон от сырья до выгрузки долгий, повторять его ради инспекции нельзя.

**Не-цели (в этом проекте)**
- Запуск CellReg / CellRegBatch, синхронайзера, поведения, INTENSE. Их объединение — отдельный будущий проект.
- Изменение алгоритмов CaImAn и логики автоинспекции (метрики, правила удаления и слияния, ML-модель).
- Перекалибровка автоподбора порогов CNMF-E. Нынешние методы `bm_qc` работают плохо; в этом проекте они только ставят стартовые значения в окне порогов.
- Новые форматы выгрузки.

**Анти-цели (провал, даже если всё работает)**
- Батч останавливается и ждёт решения человека.
- Меняется формат `npz` / `mat` / `json`, который читают синхронайзер и CellReg.
- Результаты тихо меняются: другой параметр по умолчанию, другая модель, другой порог без записи в метаданные.
- Пайплайн пишет в папку сырых данных или удаляет сырые данные.

## 3. Ограничения

- Машина: эта (Windows 11, 32 ядра, 192 ГБ ОЗУ, RTX 4070) и похожие. Одна серия обрабатывается на одной машине. Сырые данные и результаты лежат на локальных SSD.
- Сессии 5–60 минут, 20–30 кадров/с, то есть до ~108 000 кадров. Никаких лимитов на число кадров (сейчас окно ручной инспекции режет на 90 000).
- Между этапами не хранить тяжёлые TIF. Промежуточное видео — AVI без потерь (FFV1). Временный memmap, нужный CaImAn для CNMF-E, создаётся и удаляется внутри этапа.
- Порог слияния автоинспекции `pxlthr_distance_boundary` = 15 px (так обработаны данные статьи; коммит `6c26631`). Остальные параметры автоинспекции по умолчанию — производственные значения из ноутбука (ячейка capcan): `brain='hybrid'`, модель `production_models/ebm_v9_iter8.pkl`, `ml_threshold=0.72`, `n_iter=3`, `detect_corner_artifacts=False`, `correlation_method='spearman'`, `cthr=0.35`, `corr_thr=0.4`.
- Ручная инспекция (Bokeh, `bm_examinator.ExamineCells`) сохраняется: ею вручную удаляют кальциевые волны, которые автоматика не ловит.
- **FPS.** Точный FPS (по таймстемпам, без округления) — везде, кроме автоинспекции. Внутри автоинспекции FPS по-прежнему округляется до целого: с таким FPS считались признаки для обучения ML-модели и обработаны данные статьи. В метаданные пишутся оба значения. Решение автора, 2026-10-30.
- **CNMF-E: `fr` = FPS сессии при любом `tsub`.** В ноутбуке (ячейка CNMF-E) стояло `fr=fps/2` вместе с `tsub=2`; автор выяснил, что это ошибка: при `tsub=2` `fr` должен оставаться равным FPS. В новый код ошибку не переносить. Это сознательное изменение результата CNMF-E относительно старого кода; оно пишется в метаданные.

## 4. Путь серии

```
Скан ─► Аномалии ─► Батч 1: кроп + MC ─► Пороги CNMF-E ─► Батч 2: CNMF-E + автоинспекция + экспорт ─► Сводка
 (ты)     (ты)          (авто)              (ты, 1 раз)            (авто)                                (ты)
                                                                                    ▲
                    мониторинг в любой момент: прогресс, цвета, числа, логи ────────┘
```

1. **Скан.** В окне выбирают папку серии и жмут «Сканировать». Пайплайн находит сессии, группирует по мышам, проверяет видео и таймстемпы, показывает аномалии.
2. **Аномалии.** Человек удаляет или добавляет файлы, подтверждает склейку разорванных записей, исключает сессии, пересканирует.
3. **Батч 1.** Автокроп и motion correction для всех готовых сессий. В конце этапа считаются картинки для подбора порогов.
4. **Пороги.** В окне порогов человек проходит сессии и подтверждает или правит gSig, min_corr, min_pnr. Выбор пишется в конфиг сессии.
5. **Батч 2.** CNMF-E, автоинспекция, экспорт для сессий с заданными порогами. Сессии без порогов помечаются «ждёт порогов» и пропускаются, батч не ждёт.
6. **Сводка.** Та же таблица, что в мониторинге. Человек отмечает «исключить» или «переанализировать», открывает ручную инспекцию нужных сессий; после ручной инспекции сессия переэкспортируется.

Батч идёт отдельным процессом: закрытие окна его не останавливает.

## 5. Решённые части

### 5.1 Сессии и имена

- Единственный разбор имён — `naming.py` (`SESSION_PATTERN`). ID сессии: `EXP_MOUSE_DAY[_TRIAL]`, например `NOF_H01_1D`, `HOS_D04_1D_2T`. Мышь: `EXP_MOUSE`.
- Все имена выходных файлов строит один модуль путей из ID сессии и этапа. Никаких срезов вроде `name[-20:-10]`, `[:10]`, `split('/')[6:]`.
- В именах файлов нет параметров (не `..._gsig4_mincorr0.92_minpnr7_final_estimates.pickle`). Параметры — в метаданных.

### 5.2 Раскладка папки серии

Серия = одна папка. Внутри (моё решение по образцу нынешних `H:\Projects\LT1`, `G:\Projects\LNOF\CalciumData`):

| Папка | Что внутри | Кто пишет |
|---|---|---|
| `1_Raw/` | сырые видео; может содержать вложенные группы (`1_Raw/HM_NOF_1D/NOF_H01_1D/`) | человек; пайплайн только читает |
| `0_TimeStamps/` | таймстемпы по сессиям (если они лежат отдельно от видео) | человек или скан |
| `2_Cropped/` | кропнутое видео FFV1, если оно нужно MC как отдельный файл (решает исполнитель, см. 5.6) | батч 1 |
| `3_MC/` | `<SID>_MC.avi` (FFV1), сдвиги MC | батч 1 |
| `4_Estimates/` | `<SID>_estimates.pickle` после CNMF-E | батч 2 |
| `5_Inspection/<SID>/` | артефакты автоинспекции, processed-pickle, результаты и feedback ручной инспекции | батч 2, ручная инспекция |
| `6_Export/npz/` | `<SID>_data.npz`, `<SID>_metadata.json` | экспорт |
| `6_Export/filters/` | `<SID>_filters.mat` | экспорт |
| `_bearmind/` | конфиги серии, реестр сессий, логи, картинки для порогов, QC | пайплайн |

Имена папок одинаковы для всех проектов (сейчас разъезжаются: `5_Filters`/`5_Filtered`, `6_Matched`/`6_Matching`).

### 5.3 Конфиги

Три уровня, нижний перекрывает верхний:
1. **Машина**: временная папка, число ядер, память. Хранится вне репозитория и вне серии (как нынешний `config.json`, он в `.gitignore`).
2. **Серия / эксперимент**: параметры всех этапов (кроп, MC, базовый словарь CNMF-E, автоинспекция, экспорт) и пороги проверок. Лежит в `_bearmind/` серии. Создаётся из значений по умолчанию при первом скане.
3. **Сессия**: то, что отличается у сессии: пороги CNMF-E из окна, решения по аномалиям, исключение, переопределения для переанализа.

Значения по умолчанию определены в одном месте кода. Нынешние расходящиеся значения по умолчанию (`ml_threshold` 0.5 / 0.71 / 0.72, модель v6 / v9, brain ml / thresholds / hybrid, `n_iter` 2 / 3 и т. д., см. приложение А) сводятся к производственным из раздела 3.

Формат человекочитаемых конфигов — YAML с комментариями (моё решение); машинное состояние (реестр) — JSON.

Каждый запуск этапа записывает полностью разрешённые параметры этого этапа в метаданные сессии.

### 5.4 Реестр сессий

Один JSON на сессию в `_bearmind/sessions/<SID>.json` (моё решение: файлы читаются окнами, пока батч пишет; запись атомарная, через временный файл и замену). Содержит:
- ID, мышь, день/проба; список исходных папок (несколько — если запись склеена); файл таймстемпов;
- число кусков AVI, кадров в видео, строк в таймстемпах; точный FPS и его источник; длительность;
- аномалии и решения по ним (кто, когда);
- статус каждого этапа (не начат / идёт / готов / упал / пропущен), время, путь к выходам, хэш параметров этапа;
- ключевые числа этапов и предупреждения (5.11);
- флаги «исключить» / «переанализировать с этапа X».

Из реестра собирается сводная таблица серии (CSV) для решений.

### 5.5 Скан

- Рекурсивно ищет папки сессий под `1_Raw/`: имя папки разбирается `naming.py`, внутри куски `<SID>_<n>.avi` (порядок по `n`, натурально).
- Таймстемпы ищет в папке сессии (`*_Mini_TS.csv`, `*_timestamp.csv`) и в `0_TimeStamps/`. Формат в тестовых сериях — одна колонка целых, тики .NET (100 нс); исполнитель проверяет и другие форматы, которые встретит.
- FPS — точный, по медиане интервалов таймстемпов; без округления до целого. Для новых серий `fps_data.csv` не нужен.
- Аномалии (список автора):
  - число кадров в видео ≠ числу строк таймстемпов: показать разницу и где она (начало, конец, внутри);
  - нет файла таймстемпов;
  - битый последний кадр, не записались метаданные: битый кадр отбрасывается автоматически, это пишется в реестр;
  - дисконнект: несколько папок записи на одну сессию → предложить склейку по времени первого таймстемпа; пауза сохраняется в таймстемпах, чтобы не сбить синхронизацию с поведением.
- Дополнительно (моё решение): пропущенные кадры (интервал > k периодов), FPS сильно отличается от остальных сессий серии.
- Правило «у каждого куска, кроме последнего, отбросить последний кадр» (сейчас в `DoCropAndRewrite` для кадра не 608×608) не зашивать по размеру кадра. На тестовых сериях (все 608×608) кадры совпадают с таймстемпами без него. Скан решает по данным: если лишних кадров ровно «число кусков − 1», режет по кускам и пишет это в реестр; иначе — аномалия. Так же убрать зашитую обрезку 8 px сверху и слева для 608×608: поле зрения находит автокроп (моё решение).
- Пример реальной аномалии: в `H:\Projects\LT1\1_Raw\LT1_K02_1D` видео 11 848 кадров, таймстемпов 11 674, последний кусок перезаписан позже остальных.
- Из окна скана: открыть папку, исключить, принять (с обрезкой до общей длины), склеить, пересканировать. Все решения пишутся в реестр.

### 5.6 Батч 1: автокроп и motion correction

- **Автокроп.** Грубый, без GUI: найти освещённое поле зрения по проекциям подвыборки кадров и взять ограничивающий прямоугольник с запасом. Лучше обрезать меньше, чем отрезать нейроны. Если поле не найдено или подозрительно мало — предупреждение и кроп не применяется. Кроп записывается в реестр. Алгоритм — на усмотрение исполнителя.
- **MC.** Нынешняя логика `DoMotionCorrection` и параметры CaImAn без изменений; вход — склеенные куски сессии с кропом; выход `3_MC/<SID>_MC.avi` в FFV1 и сдвиги. Хранить ли кропнутое видео отдельным файлом (`2_Cropped/`) или подавать в MC иначе — решает исполнитель, с условием «без TIF».
- **Картинки для порогов** считаются в конце батча 1 по MC-видео: проекции, корреляционное изображение и PNR для каждого gSig из диапазона в конфиге. Окно порогов только показывает готовое.

### 5.7 Окно порогов

По сессиям, с переходом вперёд-назад:
1. Видео после MC с ползунком, который можно дёргать туда-сюда, как в проигрывателе.
2. Полоса картинок для gSig (диапазон из конфига, по умолчанию 3–7). Выбор кликом: соседние нейроны не сливаются в одно облако, внутри нейрона сигнал гладкий.
3. Корреляционное изображение и PNR рядом, каждое со своим ползунком; поверх — пиксели, прошедшие оба порога. Обновление на ходу, если это достаточно быстро; иначе — сетка заранее посчитанных картинок для нескольких порогов. В обоих случаях изображение видно целиком, с краями: шумные пиксели обычно на периферии.
4. Счётчики: число «облачков» выше обоих порогов, доля одиночных шумовых пикселей.
5. Стартовые значения ставит автоподбор (нынешние методы `bm_qc`). Кнопки «принять → следующая», «принять для всех сессий мыши».

Каждый выбор записывается рядом с тем, что предлагал автоподбор: это данные для будущей калибровки автоподбора.

### 5.8 Батч 2: CNMF-E, автоинспекция, экспорт

- **CNMF-E**: нынешняя логика `DoCNMF` (CaImAn) без изменений алгоритма; базовый словарь параметров из конфига серии (взять из ячейки ноутбука, где собирается `cnmf_dict`), пороги из конфига сессии. `fr` = точный FPS сессии, `tsub` из конфига, `fr` на `tsub` не делится (раздел 3). memmap во временной папке машины, удаляется после этапа. В estimates не хранить абсолютный путь к видео, по которому потом что-то ищется (сейчас `tif_name` ломает QC и перезапуски при переносе данных).
- **Автоинспекция**: `run_auto_inspection` с производственными параметрами (раздел 3); выходы в `5_Inspection/<SID>/`.
- **Экспорт**: одна функция вместо нынешних четырёх копий (ноутбук ×2, `batch_export.py`, CLI в `export_estimates_data.py`): ML-фильтр + feedback ручной инспекции → `npz`, `json`, `mat`.
  - Поля и структура `npz` и `mat` не меняются.
  - В `json` поля не убираются; добавляются поля происхождения (5.12).
  - `fps` в `json` — точный (19.76, а не 20, как сейчас из-за округления). Это исправление значения, не формата. FPS, с которым шла автоинспекция, пишется отдельным полем.
  - Рядом с `npz` пишутся таймстемпы, выровненные кадр в кадр с выгруженными трейсами: `<SID>_timestamps.csv` в формате `Mini_TS` (одна колонка тиков, без заголовка). Тогда склейка записей, отброшенный битый кадр и обрезка не собьют синхронизацию с поведением. Исходные таймстемпы не меняются (моё решение).

### 5.9 Ручная инспекция

- Остаётся нынешнее окно Bokeh. Меняется только обвязка: открывается из сводки для выбранной сессии; читает processed-pickle из `5_Inspection/<SID>/`; сохраняет результат и `feedback.csv` туда же, а не в текущую папку; без лимита кадров (`end_frame`).
- После сохранения сессия помечается «переэкспортировать», и экспорт обновляется.
- Предупреждение «похоже на кальциевую волну» (много компонент вспыхивает одновременно) — подсказка, какие сессии открыть; удаляет по-прежнему человек. Желательно, не обязательно в первой версии.

### 5.10 Запуск, продолжение, переанализ

- Батч — отдельный фоновый процесс, запускается из окна (и из командной строки). Сессии идут по одной; внутри сессии параллелит CaImAn.
- Этап сессии считается готовым, если его выходы есть, статус «готов» и хэш параметров совпадает. Иначе этап и все следующие пересчитываются.
- Ошибка в этапе сессии ловится, трейсбек пишется в лог сессии, статус «упал», следующие этапы этой сессии — «пропущено», батч идёт к следующей сессии.
- Переанализ: в сводке выбирают сессии, меняют параметры (переопределения в конфиге сессии), задают этап, с которого начать. Старый результат не затирается, пока новый не готов.
- Логи: лог серии и лог каждой сессии в `_bearmind/logs/`; файл-«пульс» для индикатора «работает».

### 5.11 Проверки после этапов

Батч никогда не ждёт человека. Уровни: «норма», «предупреждение», «ошибка» (этап упал или результат совсем вне разумного). Пороги проверок — в конфиге серии; бывают абсолютные (сдвиг > N px) и относительные (сессия выбивается из медианы серии в K раз).

| Этап | Проверки | Ключевое число в таблице |
|---|---|---|
| Скан | аномалии из 5.5 | — |
| Кроп | поле зрения не найдено или слишком мало | размер кропа |
| MC | слишком сильный сдвиг между кадрами; после коррекции кадры плохо совпадают со средним | макс. сдвиг |
| CNMF-E | аномально много компонент (пороги плохие); много пропущенных клеток в остатке (`bm_qc` уже считает) | число компонент; gSig, min_corr, min_pnr |
| Автоинспекция | необычно большая доля удалённых компонент; подозрение на кальциевую волну | принято (и % удалённых) |
| Экспорт | мало нейронов | нейронов; медиана SNR |

Все результаты проверок и все решения человека пишутся в реестр и в метаданные экспорта.

### 5.12 Происхождение результатов

### 5.13 Окна

Моё решение: одна настольная программа на Python (Qt), вкладки «Скан», «Пороги», «Мониторинг / сводка»; запуск ярлыком или `.bat`. Ручная инспекция открывается из сводки в своём нынешнем окне.

**Мониторинг** (по наброску, согласованному с автором):
- вверху: «работает, обновлено N с назад», текущая сессия и этап, прогресс, оценка оставшегося времени, счётчики предупреждений и ошибок;
- таблица: строки — сессии, сгруппированные по мышам; столбцы — этапы; в клетке цвет и ключевое число (5.11), а также пороги CNMF-E и медиана SNR;
- наведение на цветную клетку объясняет причину («2950 компонент, в 4.8 раза больше медианы серии»);
- просмотр логов серии и сессии;
- в конце серии та же таблица — сводка: отметки «исключить», «переанализировать», кнопка ручной инспекции, выгрузка сводки в CSV.

  - MC: `3_MC/<SID>_CR_MC.tif`; `2.2_MC_Combined/<SID>_CR_MC.mp4` — только для просмотра (mp4 с потерями, CNMF-E по нему не запускать);
