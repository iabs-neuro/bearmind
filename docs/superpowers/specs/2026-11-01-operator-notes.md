# Заметки оператора bearmind

Короткие инструкции для того, кто запускает серии. Фаза 6 перенесёт их в руководство студента.

## Как поменять кроп мыши

У всех сессий одной мыши одна рамка кропа. Размер рамки записан в конфиге мыши. Это файл `_bearmind/config/mice/<МЫШЬ>.yaml`, ключ `crop.box`: высота и ширина в пикселях. Положение рамки в каждой сессии записано в конфиге сессии, ключ `crop.box_pos`.

Ключ `crop.box_source` говорит, кто задал размер. `auto` — размер посчитал пайплайн. `manual` — размер задал человек. Если ключа нет, пайплайн считает размер автоматическим.

Перед правкой остановите батч (Ctrl+C) или дождитесь конца прогона. Причина: батч перечитывает конфиги на каждом шаге.

### Задать свой размер рамки

1. Откройте конфиг мыши в текстовом редакторе.
2. Впишите новый размер в `crop.box`, например `box: [480, 500]`.
3. Впишите строку `box_source: manual`. Тогда пайплайн не заменит ваш размер.
4. Сохраните файл.
5. Запустите `run_bearmind run <СЕРИЯ>`.

Батч заново поставит рамку в каждой сессии мыши: по центру поля зрения и внутри кадра. Затем он заново сделает MC и все следующие этапы этих сессий.

Задавайте размер не больше кадра сессий этой мыши.

### Вернуть автоматический размер

1. Откройте конфиг мыши.
2. Удалите строки `box` и `box_source`.
3. Сохраните файл.
4. Запустите `run_bearmind run <СЕРИЯ>`.

Пайплайн посчитает размер по полям зрения всех сессий мыши. Если новый размер равен старому, MC не повторяется.

### Поменять порог поиска поля зрения

1. Впишите новое значение `crop.fov_threshold_frac` в конфиг мыши. Для всех мышей серии впишите его в `_bearmind/config/series.yaml`.
2. Запустите `run_bearmind run <СЕРИЯ>`.

Батч заново найдёт поле зрения во всех сессиях мыши. При `box_source: auto` он заново посчитает размер рамки. При `box_source: manual` размер останется вашим, изменятся только положения рамки. Так же работают `min_fov_frac`, `margin_px` и настройки метода `activity`: `sample_frames`, `activity_mass_cut` и `activity_margin_px`.

Метод `fov_method: activity` ищет поле зрения по кальциевой активности внутри освещённой области. Он читает три окна кадров: в начале, в середине и в конце сессии. В сумме он читает `sample_frames` кадров. `activity_mass_cut` задаёт, какую долю активности можно отрезать по краям. `activity_margin_px` добавляет запас вокруг найденного поля. Метод `brightness` ищет только освещённую область. Он нужен, если надо вернуть старое правило.

### Обзор кропа

После каждой расстановки рамок батч рисует обзор серии: `_bearmind/crop_overview.png`. У каждой сессии там две панели: средний кадр и карта активности. Жёлтый пунктир — освещённая область. Зелёный пунктир — поле (`crop.fov`). Голубая линия — рамка мыши. Белые точки — сильные зерна, то есть явные клетки. Красная точка — сильное зерно вне рамки мыши.

Посмотрите обзор один раз после первого кропа серии:

1. Откройте `_bearmind/crop_overview.png`.
2. Проверьте, что голубая рамка охватывает всю ткань с клетками.
3. Проверьте, что красных точек нет. Подпись сессии с такими точками тоже красная.

Подпись сессии: `<SID>  box ВЫСОТАxШИРИНА  (<fov_method>, pos/neg <число>)`. Значения `fov_method`:

- `activity` — поле найдено по кальциевой активности;
- `fallback_pos_neg` — активность не отличается от шума (`pos/neg` меньше 8), поле равно освещённой области;
- `fallback_small` — поле активности меньше четверти освещённой области, поле равно освещённой области;
- `brightness` — в конфиге задан метод яркости, поле равно освещённой области;
- `no_lit_area` — освещённой области нет, сессия идёт без кропа.

Если рамка режет клетки, задайте размер рамки вручную (раздел «Задать свой размер рамки»). Другой путь — вписать `crop.fov_method: brightness`.

### Что пайплайн делает сам

- Рамку удалили, а положения остались. MC ждёт (`waiting for crop_finalize`) и не идёт без кропа. Батч сам ставит рамку заново.
- Размер поменяли руками, но не вписали `box_source`. Если рамки уже стояли, пайплайн заметит правку и сам запишет `manual`.
- Целым кадром, без кропа, идёт только сессия без найденного поля зрения. У неё есть аномалия `fov_not_found`.
- Рамку, с которой MC работал на самом деле, показывает колонка `crop_box` в `_bearmind/summary.csv`.

## Превью

Превью — пять видео для просмотра: четыре видео MC (`raw`, `raw_dff`, `mc`, `mc_dff`) и QC-видео CNMF-E (`cnmf_qc`). По умолчанию батч их не делает. Причина: на сессии в 10 мин видео занимали около половины времени этапа MC и 3 ГБ диска на серию из шести сессий.

PNG карт остатков (`Preview/<SID>_cnmf_residual.png`) батч делает всегда. Из него считается проверка `cnmf_missed_cells`.

### Включить превью

Предупреждение: превью занимают много времени, пока они идут, карты порогов не строятся. Оба превью стоят около 48 мс на кадр: примерно 1 ч на часовую сессию. Для 24 сессий LT1 это около 13 ч. Включайте превью, когда эти часы не мешают.

1. Выполните `run_bearmind previews <СЕРИЯ> on` или отметьте флажок «Preview videos» в окне серии.
2. Запустите `run_bearmind run <СЕРИЯ>`. Если батч уже идёт, ничего не делайте. Он прочитает флажок после текущего этапа, а если ждёт человека — в течение 30 с.

Батч сделает превью для каждой сессии с готовым MC и CNMF-E. MC и CNMF-E он не повторяет. Видео лежат в папке `Preview/`.

Батч идёт по серии этап за этапом. При включённых превью порядок такой:

1. MC всех сессий.
2. Превью MC (`mc_preview`) всех сессий.
3. Карты порогов.
4. CNMF-E.
5. Превью CNMF-E (`cnmf_preview`).

Если вы отметили флажок посреди прогона, все ожидающие превью встают перед оставшимися основными этапами. Карты порогов ждут, пока они не закончатся.

Размер превью задают два ключа:

- `--tbin N` — сколько кадров усредняется в один кадр превью. По умолчанию 2.
- `--ssub N` — сколько пикселей по стороне усредняется в один пиксель превью. По умолчанию 1, то есть полный размер.

Пример: `run_bearmind previews <СЕРИЯ> on --ssub 2`. Новая настройка переделывает только превью.

### Выключить превью

1. Выполните `run_bearmind previews <СЕРИЯ> off` или снимите флажок.

Готовые файлы превью остаются. В `_bearmind/summary.csv` столбцы `mc_preview` и `cnmf_preview` показывают `off`. В `run_bearmind status` столбец `pv` показывает `off`.

### Если превью упало

Сессия идёт дальше до экспорта: превью ничего не держит. Сбой видно в `status`, в `summary.csv` и в панели предупреждений окна.

1. Устраните причину, например освободите диск.
2. Выполните `run_bearmind retry <СЕРИЯ> <SID>` или нажмите Retry в окне. Батч повторит только превью.

## Если CNMF-E понизил фон

Аномалия `cnmf_downsampled` значит: фильм сессии не влезает в бюджет памяти CNMF-E при настроенном `cnmf.ssub_B`, поэтому батч сам взял более сильное понижение фона. `ssub_B` — во сколько раз по стороне уменьшается модель фона в шаге `compute_W` CaImAn. Нейроны (`A` и `C`) остаются в полном разрешении. Бюджет — ключ `cnmf_ram_budget_gb` в `machine.yaml`.

Случается это на длинных сессиях с большой рамкой. Пример: часовая сессия 107 107 кадров с рамкой 567×520 при бюджете 153 ГиБ получает `ssub_B 3`.

- Уровень warning: батч взял `ssub_B` 3 или 4, предсказание памяти влезает в бюджет. Делать ничего не нужно.
- Уровень error: предсказание не влезает даже при `ssub_B` 4. Этап всё равно идёт, но памяти может не хватить.

Значение `ssub_B` и предсказание памяти показывает подсказка клетки CNMF-E в окне. Те же числа лежат в реестре сессии: метрики `ssub_B` и `need_gib` этапа cnmf.

Если аномалия уровня error или понижение нежелательно:

1. Сузьте рамку мыши (раздел «Задать свой размер рамки»). Причина: память `compute_W` растёт с площадью рамки.
2. Или запустите серию на машине с большей памятью.

Если сессия, близкая к пределу памяти, перешла на другую машину, её CNMF-E пересчитывается. Тогда заново запрашивается и решение ворот (R28) этой сессии.

`ssub_B` входит в параметры этапа cnmf. Поэтому на машине с другим объёмом памяти CNMF-E такой сессии может пересчитаться. Сессий, которые влезают в обе машины, это не касается.

## После обновления bearmind

Удалите вручную старые временные папки `<temp_dir>/<SID>` от этапов, прерванных до обновления. Батч их больше не удаляет: новые папки называются `<хэш серии>_<SID>`. Одна такая папка может занимать до 160 ГБ и уменьшает свободное место, которое проверяется перед этапом. Путь `temp_dir` записан в `machine.yaml`.

## Один батч на машину

На машине одновременно идёт один батч. Причина: карты порогов и CNMF-E берут весь бюджет памяти `cnmf_ram_budget_gb`, и два батча вместе не влезают в память. Второй запуск (`run_bearmind run` или кнопка Start) отказывает и называет серию и PID первого батча. Блокировка лежит в `<BEARMIND_HOME>/runner.lock` (по умолчанию `~/.bearmind/runner.lock`). Упавший батч её не держит.

## После обновления A2

Обработанные серии один раз заново проходят кроп, затем MC, карты порогов и CNMF-E. Пороги, заданные человеком, используются снова. Каждые ворота ждут нового решения (R28). Превью остаются выключенными, пока вы их не включите.

## После обновления 2026-11: правило экспорта

Экспорт выбирает нейроны по правилу `ml_or_merged_not_deleted`. Нейрон попадает в экспорт, если выполнены оба условия:

- вероятность ML не ниже порога автоинспекции, или нейрон получен слиянием (`decision: from_merge`);
- автоинспекция не пометила нейрон на удаление (`delete` не равно 1).

Старое правило `ml_probability` проверяло только вероятность. С ним в экспорт попадали тусклые копии соседних нейронов (SNR-дубли), а нейроны от слияний терялись. Новое правило одно для `run_bearmind`, `export_estimates_data.py`, ноутбука и `batch_export.py`.

Имя правила входит в параметры этапа export, а ключ `seed` и версия группировки слияний (`merge_grouping`) — в параметры этапа autoinspect. Поэтому следующий запуск заново делает автоинспекцию и экспорт всех готовых сессий. MC, пороги и CNMF-E не повторяются.

1. Запустите `run_bearmind run <СЕРИЯ>`.
2. Дождитесь конца прогона. Автоинспекция одной сессии на 2000 кадров занимает около 70 с, полной сессии — дольше. Экспорт занимает около 10 с.
3. Откройте `_bearmind/summary.csv`. Числа в столбце `export_n_neurons` изменятся.

Ручную инспекцию повторять не нужно: автоинспекция берёт тот же вход. В json экспорта поля `n_snr_duplicates_exported` и `n_merge_products_dropped` теперь равны 0. Если в каком-то файле там не 0, в сводке есть аномалия `export_rule_counters`: сообщите разработчику.

### Что изменилось в автоинспекции

- Новый ключ `autoinspect.seed` (по умолчанию 0) задаёт шум, который библиотека driada добавляет к трейсам. Два прогона на одних данных с одними версиями библиотек дают одинаковые решения; порядок проверки пар теперь не зависит от машины. Раньше число нейронов менялось от прогона к прогону (117 или 118 на NOF_H01_1D).
- Группа слияния содержит только компоненты, которые все попарно близки: расстояние между границами не больше 15 px, различие SNR не больше 10. Цепочка близких пар делится на несколько тесных групп. Раньше в одну группу попадали далёкие клетки из одного кластера корреляций. После этого обновления автоинспекция и экспорт повторяются при следующем запуске. MC, пороги и CNMF-E не повторяются.

Не меняйте `seed` без причины. Другое значение даёт другой, но тоже воспроизводимый результат и заново запускает автоинспекцию всех сессий.

### Старые обработанные файлы

Обработанный файл, сделанный до 2026-11-07 (с цепочками слияния или без ключа `merge_grouping`), надо снова провести через автоинспекцию, прежде чем экспортировать его продукты слияния. До этого экспорт оставляет такие продукты вне файла и пишет предупреждение `[WARN] ... merge products not exported`. В `run_bearmind` автоинспекция запускается сама, поэтому там это не случается; аномалия `old_merge_grouping` — страховка. Ячейки ноутбука `BEARMiND_full_pipeline.ipynb` не менялись: они используют прежнее правило `ml_approved_components` и не знают об этом ограничении.

## После обновления 2026-11: проверка частоты кадров

Скан сравнивает частоту кадров сессии с другими сессиями её мыши, а не всей серии. Разные мыши одной серии и одна мышь в разные дни могут писаться с разной частотой, это нормально. Сессия получает `fps_outlier`, только если ни одна другая сессия мыши не записана с близкой частотой (в пределах `scan.fps_series_dev`, 5 %). Если у мыши меньше трёх сессий с частотой (ключ `checks.min_sessions_for_relative`), скан её сессии не проверяет. Старые предупреждения `fps_outlier` остаются в реестре до следующего скана. Чтобы применить новое правило, запустите `run_bearmind scan <СЕРИЯ>`. Скан не меняет результаты этапов.

## Размер пула MC

Этап MC запускает 16 рабочих процессов CaImAn. Это значение ключа `pool.mc_processes`. На машине с N логическими процессорами процессов будет не больше N - 1.

Чтобы задать другой размер для серии, впишите `pool: {mc_processes: 8}` в `_bearmind/config/series.yaml`. Размер пула не входит в параметры этапа MC: сдвиги от него не зависят. Поэтому смена размера не запускает MC заново.

## Не удаляйте видео MC

Не удаляйте видео MC (`3_MC/<сессия>_MC.avi`), чтобы освободить место на диске. Без этого файла батч повторяет MC и все следующие этапы сессии, включая CNMF-E и невоспроизводимую автоинспекцию, а ворота снова ждут решения по ручной инспекции.

## Рисунки в процессах этапов

Батч и процессы этапов рисуют через matplotlib без Qt (`MPLBACKEND=Agg`): с Qt процесс CNMF-E падал при выходе, Windows писала дамп ~100 МБ, а этап записывался на ~30 с позже.
