# Заметки оператора bearmind

Короткие инструкции для того, кто запускает серии. Фаза 6 перенесёт их в руководство студента.

## Как поменять кроп мыши

У всех сессий одной мыши одна рамка кропа. Размер рамки записан в конфиге мыши. Это файл `_bearmind/config/mice/<МЫШЬ>.yaml`, ключ `crop.box`: высота и ширина в пикселях. Положение рамки в каждой сессии записано в конфиге сессии, ключ `crop.box_pos`.

Ключ `crop.box_source` говорит, кто задал размер. `auto` — размер посчитал пайплайн. `manual` — размер задал человек. Если ключа нет, пайплайн считает размер автоматическим.

Перед правкой остановите батч (Ctrl+C) или дождитесь конца прогона. Причина: батч перечитывает конфиги на каждом шаге.

### Задать свой размер рамки

1. Откройте конфиг мыши в текстовом редакторе.
2. Впишите новый размер в `crop.box`, например `box: [480, 500]`.
3. Впишите строку `box_source: manual`. Тогда пайплайн не заменит ваш размер.
4. Сохраните файл.
5. Запустите `run_bearmind run <СЕРИЯ>`.

Батч заново поставит рамку в каждой сессии мыши: по центру поля зрения и внутри кадра. Затем он заново сделает MC и все следующие этапы этих сессий.

Задавайте размер не больше кадра сессий этой мыши.

### Вернуть автоматический размер

1. Откройте конфиг мыши.
2. Удалите строки `box` и `box_source`.
3. Сохраните файл.
4. Запустите `run_bearmind run <СЕРИЯ>`.

Пайплайн посчитает размер по полям зрения всех сессий мыши. Если новый размер равен старому, MC не повторяется.

### Поменять порог поиска поля зрения

1. Впишите новое значение `crop.fov_threshold_frac` в конфиг мыши. Для всех мышей серии впишите его в `_bearmind/config/series.yaml`.
2. Запустите `run_bearmind run <СЕРИЯ>`.

Батч заново найдёт поле зрения во всех сессиях мыши. При `box_source: auto` он заново посчитает размер рамки. При `box_source: manual` размер останется вашим, изменятся только положения рамки. Так же работают `min_fov_frac`, `margin_px` и настройки метода `activity`: `sample_frames`, `activity_mass_cut` и `activity_margin_px`.

Метод `fov_method: activity` ищет поле зрения по кальциевой активности внутри освещённой области. Он читает три окна кадров: в начале, в середине и в конце сессии. В сумме он читает `sample_frames` кадров. `activity_mass_cut` задаёт, какую долю активности можно отрезать по краям. `activity_margin_px` добавляет запас вокруг найденного поля. Метод `brightness` ищет только освещённую область. Он нужен, если надо вернуть старое правило.

### Что пайплайн делает сам

- Рамку удалили, а положения остались. MC ждёт (`waiting for crop_finalize`) и не идёт без кропа. Батч сам ставит рамку заново.
- Размер поменяли руками, но не вписали `box_source`. Если рамки уже стояли, пайплайн заметит правку и сам запишет `manual`.
- Целым кадром, без кропа, идёт только сессия без найденного поля зрения. У неё есть аномалия `fov_not_found`.
- Рамку, с которой MC работал на самом деле, показывает колонка `crop_box` в `_bearmind/summary.csv`.

## После обновления bearmind

Удалите вручную старые временные папки `<temp_dir>/<SID>` от этапов, прерванных до обновления. Батч их больше не удаляет: новые папки называются `<хэш серии>_<SID>`. Одна такая папка может занимать до 160 ГБ и уменьшает свободное место, которое проверяется перед этапом. Путь `temp_dir` записан в `machine.yaml`.

## После обновления 2026-11: правило экспорта

Экспорт выбирает нейроны по правилу `ml_or_merged_not_deleted`. Нейрон попадает в экспорт, если выполнены оба условия:

- вероятность ML не ниже порога автоинспекции, или нейрон получен слиянием (`decision: from_merge`);
- автоинспекция не пометила нейрон на удаление (`delete` не равно 1).

Старое правило `ml_probability` проверяло только вероятность. С ним в экспорт попадали тусклые копии соседних нейронов (SNR-дубли), а нейроны от слияний терялись. Новое правило одно для `run_bearmind`, `export_estimates_data.py`, ноутбука и `batch_export.py`.

Имя правила входит в параметры этапа export, а ключ `seed` и версия группировки слияний (`merge_grouping`) — в параметры этапа autoinspect. Поэтому следующий запуск заново делает автоинспекцию и экспорт всех готовых сессий. MC, пороги и CNMF-E не повторяются.

1. Запустите `run_bearmind run <СЕРИЯ>`.
2. Дождитесь конца прогона. Автоинспекция одной сессии на 2000 кадров занимает около 70 с, полной сессии — дольше. Экспорт занимает около 10 с.
3. Откройте `_bearmind/summary.csv`. Числа в столбце `export_n_neurons` изменятся.

Ручную инспекцию повторять не нужно: автоинспекция берёт тот же вход. В json экспорта поля `n_snr_duplicates_exported` и `n_merge_products_dropped` теперь равны 0. Если в каком-то файле там не 0, в сводке есть аномалия `export_rule_counters`: сообщите разработчику.

### Что изменилось в автоинспекции

- Новый ключ `autoinspect.seed` (по умолчанию 0) задаёт шум, который библиотека driada добавляет к трейсам. Два прогона на одних данных с одними версиями библиотек дают одинаковые решения; порядок проверки пар теперь не зависит от машины. Раньше число нейронов менялось от прогона к прогону (117 или 118 на NOF_H01_1D).
- Группа слияния содержит только компоненты, которые все попарно близки: расстояние между границами не больше 15 px, различие SNR не больше 10. Цепочка близких пар делится на несколько тесных групп. Раньше в одну группу попадали далёкие клетки из одного кластера корреляций. После этого обновления автоинспекция и экспорт повторяются при следующем запуске. MC, пороги и CNMF-E не повторяются.

Не меняйте `seed` без причины. Другое значение даёт другой, но тоже воспроизводимый результат и заново запускает автоинспекцию всех сессий.

### Старые обработанные файлы

Обработанный файл, сделанный до 2026-11-07 (с цепочками слияния или без ключа `merge_grouping`), надо снова провести через автоинспекцию, прежде чем экспортировать его продукты слияния. До этого экспорт оставляет такие продукты вне файла и пишет предупреждение `[WARN] ... merge products not exported`. В `run_bearmind` автоинспекция запускается сама, поэтому там это не случается; аномалия `old_merge_grouping` — страховка. Ячейки ноутбука `BEARMiND_full_pipeline.ipynb` не менялись: они используют прежнее правило `ml_approved_components` и не знают об этом ограничении.

## После обновления 2026-11: проверка частоты кадров

Скан сравнивает частоту кадров сессии с медианой её мыши, а не всей серии. Разные мыши одной серии могут писаться с разной частотой, это нормально. Если у мыши меньше трёх сессий с частотой (ключ `checks.min_sessions_for_relative`), скан её сессии не проверяет. Старые предупреждения `fps_outlier` остаются в реестре до следующего скана. Чтобы применить новое правило, запустите `run_bearmind scan <СЕРИЯ>`. Скан не меняет результаты этапов.

## Размер пула MC

Этап MC запускает 16 рабочих процессов CaImAn. Это значение ключа `pool.mc_processes`. На машине с N логическими процессорами процессов будет не больше N - 1.

Чтобы задать другой размер для серии, впишите `pool: {mc_processes: 8}` в `_bearmind/config/series.yaml`. Размер пула не входит в параметры этапа MC: сдвиги от него не зависят. Поэтому смена размера не запускает MC заново.
