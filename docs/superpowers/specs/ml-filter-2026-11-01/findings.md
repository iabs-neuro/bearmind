# ML-фильтр экспорта и решения автоинспекции (2026-11-01)

Расследование только чтением, по коду, истории git и данным. Скрипты и их вывод лежат в этой папке: `analyze.py`, `merge_spread.py`, `old_corpus.py` (+ `old_corpus_out.txt`), `merge_spread_corpus.py` (+ `merge_spread_out.txt`). Корпус — боевой прогон мая 2026 (CC, RFC, FOF, 106 сессий).

## Итог

1. **Двойного фильтра нет.** Автоинспекция ничего не удаляет. `implement_decision` оставляет компоненты с `delete=1` в `idx_components` (auto_inspector.py:1889-1891, 1935; коммит d273702 «keep deleted neurons visible», сделано ради окна ExamineCells). Решение автоинспекции применяет только ML-фильтр экспорта (5ab5e7a).
2. **Новый экспорт в точности повторяет старый.** На 106 из 106 сессий мая 2026 правило `P >= 0.72` даёт ровно число экспортированных нейронов (17141). Feedback не было ни в одной сессии.
3. **Правило `P >= 0.72` расходится со столбцом `delete` в двух классах:**
   - SNR-дубли (тусклая копия ближе 15 px к яркому коррелированному соседу) имеют `delete=1` при `P >= 0.72` и экспортируются. В данных статьи их 1041 из 17141 (6,1 %).
   - Продукты слияния (`decision='from_merge'`, `P=NaN`, `delete=0`) не экспортируются никогда. Исходные компоненты слияния тоже не экспортируются: `manual_merge` убирает их из оценок. В данных статьи пропали 2506 слитых нейронов из 10930 исходных компонент, и у всех исходных было `P >= 0.72`.
4. **Группировка слияний склеивает далёкие компоненты.** Группа слияния — вся компонента связности графа корреляций (auto_inspector.py:996-1015, 1851-1855). В корпусе 194 из 2506 групп не связны по рёбрам FBD <= 15 px. В них 4936 из 10930 исходных компонент. В RFC есть группа из 256 компонент. В NOF_H03_3D (тестовая серия) 8 компонент с разбросом центров 229 px стали одной. Исправлено: см. раздел «Обновление 2026-11-06: группы слияния по соседству».
5. **Покомпонентные массивы в processed pickle перепутаны.** `SNR_comp`, `r_values`, `bl`, `c1`, `neurons_sn`, `g` не совпадают по порядку с A и C. CaImAn `manual_merge` не обновляет `SNR_comp` и `r_values`. Сжатие берёт `arr[:N]` вместо `arr[good]` (estimates_compression.py:99-113). `metrics_df` верен: он посчитан до слияния и сжатия, на несжатом входе.
   - Проверка контроллера: входы боевой автоинспекции (`H:\Dataset\CalciumData\{RFC,CC,FOF}\4_Estimates_refined`, 9 из 9 проверенных файлов) не сжаты. Длина `SNR_comp` равна числу столбцов A, атрибута `idx_components_bad_original` нет. Значит, признаки ML-модели в данных статьи посчитаны правильно. `export_estimates_data.py` перепутанные массивы не использует.

## Старый процесс

- Порядок ноутбука: CNMF-E -> сжатие (по желанию) -> автоинспекция (compress=True) -> ExamineCells в режиме capcan (цвет по ML-вероятности) -> пакетный экспорт `*_processed.pickle`. Боевой путь MINI3 тот же: `batch_autoinspect_all.py` (вход `Estimates_refined`) -> `batch_export_all.py` -> `export_one`.
- Экспорт читал `_processed.pickle` (batch_export.py:50). Ручная правка шла только через feedback.csv, и feedback применялся после ML-фильтра.
- Сохранение в ExamineCells пометки `delete` не применяет. Цвет в окне зависит только от P, поэтому SNR-дубли зелёные, а продукты слияния серые.
- История: f02c8b9 (2026-01-02) — экспорт без фильтра; 5ab5e7a (2026-01-12) — «Add ML threshold filtering (default 0.72) to remove low-confidence neurons».

## Обновление 2026-11-06: группы слияния по соседству

Группа слияния теперь — компонента связности пар с FBD <= 15 px и |dSNR| <= 10 среди неудалённых компонент одного кластера корреляций. Удаления SNR-дублей остались прежними. Новая функция `assign_merge_groups` в `auto_inspector.py`. Пересчитана только группировка по сохранённым csv, FBD и FCD. Автоинспекция не запускалась. Скрипт: `merge_regroup.py`, вывод: `merge_regroup_out.txt`. Решения «мозга» восстановлены из csv по `ml_keep_probability` и столбцам `failed_*`.

Удаления совпали с сохранёнными в 103 из 106 сессий корпуса и в 2 из 2 сессий series_short. В трёх сессиях (CC_H01_1D, RFC_F20_1D, RFC_F26_3D) расходятся 5 строк. У них P = 0,96-0,999 и нет флагов `failed_*`. Старый и новый шаг слияния дают на восстановленном входе одинаковые удаления, но оба расходятся с сохранённым csv: SNR-проигравший в близкой паре — другой член. Вероятная причина, НЕ проверена: порядок строк внутри кластера корреляций после `sort_values` (быстрая сортировка, не стабильная; у всех членов кластера одно значение `corr_groups`) различается между NumPy 1.26 (прогон мая 2026) и NumPy 2 (этот пересчёт). В цепочках правило SNR-проигравшего зависит от этого порядка. Стабильную сортировку не добавляли.

| CC | 33 | 32 | 1463 -> 1574 | 4396 -> 4376 | 47 -> 16 | 83 -> 0 | 400 -> 64 | 74 -> 39 | 19 -> 0 |
| FOF | 21 | 21 | 329 -> 393 | 893 -> 883 | 53 -> 7 | 18 -> 0 | 377 -> 30 | 13 -> 1 | 10 -> 0 |

Число групп растёт: одна склеенная группа распадается на несколько цепочек. В RFC число групп с разбросом > 30 px выросло с 97 до 152 по той же причине: цепочка близких пар может растянуться больше чем на 30 px между центрами. Максимальный разброс центров упал везде. Последствие: после повторной автоинспекции число продуктов слияния в сессии равно числу групп «после».
